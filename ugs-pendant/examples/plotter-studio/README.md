# Plotter Studio — Dashboard plugin

Version 0.5.52. A fork of the **SVG to G-code** plugin (0.7.2) aimed at pen plotting. The original `svg-to-gcode` plugin is unchanged and still installs separately; this one has its own id (`plotter-studio`), its own saved presets, and is where new plotter features go. Everything the original does (SVG and 2D DXF import, drag knife, laser, ordering, endpoint joining, presets, Save As) still works the same way; see `../svg-to-gcode/README.md` for those details.

It generates millimeter, absolute-coordinate G-code for inspection in the UGS Dashboard. It never sends machine commands or starts a job.

## What is new: color to pen

Every imported path now carries a color.

- **SVG:** the stroke color, else the fill color. Both are inherited from parent groups, as in SVG itself. Hex (`#f00`, `#ff0000`), `rgb()` and the common named colors are understood. Gradients, patterns, `currentColor` and CSS classes cannot be resolved and plot as black.
- **DXF:** the entity's true color, else its explicit AutoCAD color index, else its layer's color. Color 7 (white/black in CAD) plots black.
- **Endpoint joining** (Quality tab) and DXF line/arc joining never join paths of different colors.

The new **Pens** tab lists every color with its path count and a **Pen** number:

- Each color starts on its own pen, numbered in order of appearance.
- Type the same number for several colors to put them on one pen. Several shades of red can share a pen.
- **Plot checkbox / pen 0 skips** a color entirely: untick the box on its row (or enter pen 0) and its outlines, its hatch and its claim on shared lines all disappear, so a white pen costs nothing. Unticking remembers the pen number and ticking restores it. **Skip white** unticks every near-white color at once (white paper), and **Plot all colors** turns everything back on. A skipped shape still counts as part of the picture for hidden-line removal, so it keeps hiding what lies beneath it.
- **One pen per color** and **All on pen 1** reset the table. Assignments survive a Reimport for colors that still exist.
- **Group colors** (Pens tab): enter how many pens you have under **Pens available** and click **Group colors**. Similar colors are merged onto that many pens, so several shades of red end up on one pen.
  - **How:** k-means clustering in the CIE Lab color space, where distances follow how colors look rather than their RGB numbers. Colors used by more paths count for more, and the result is repeatable: the same artwork and number always give the same grouping.
  - **Numbering:** pens are numbered in order of first appearance in the artwork.
  - **Display colors:** each pen's colors are shown (preview, swatches, G-code pen comments) as the pen's most representative color from the artwork. Click a swatch to choose another. In **Consolidated pens**, click that row's **Auto** button to restore only its area-weighted representative color without regrouping or changing assignments; **One pen per color** restores every original color and assignment.
  - **Skipped colors** (pen 0) stay skipped and are left out of the active grouping. Their existing groups are parked on unused numbers after the new active pen range, so they remain visible as unchecked consolidated rows and do not count against **Pens available** until restored. Asking for more active pens than there are enabled colors gives each enabled color its own pen. After grouping you can still edit any pen number by hand.
  - **Black, grays and white come first:** colors with almost no chroma (black, grays, white) are grouped on their own and get their own pens before any chromatic color gets an extra pen. Distinct tones (for example black, mid gray and white) each get a pen; near-duplicates such as `#000000` and `#111111` share one. When a meaningful near-black or near-white region shares a reduced group with intermediate grays, the endpoint is kept as the physical representative pen color; a microscopic tracing speck is ignored. Only the pens left over are shared out among the chromatic colors, so a light blue can never take a pen ahead of black. With only one pen, everything shares it; with two or more, the neutrals never share a pen with a chromatic color. If you have fewer pens than neutral tones, the neutrals share the one pen that is left after reserving one for the chromatic colors.
- Pens apply in **plotter mode** only. Knife and laser modes ignore the table.
- The preview draws plotter paths in their color.

Pens are plotted in number order, and a pen is finished before the next starts. Path ordering (Reduce travel, Inner contours first, Largest closed contour last) and start points apply within each pen. Inner-first never waits on a path of another pen.

## Pen changes

**When the pen changes** (Pens tab):

| Option | Output |
| --- | --- |
| Pause (M0) | Before every pen group, including the first: lift to Safe Z, a comment line such as `(Pen 2: dark green #154c2a)`, then `M0 (MSG, Load pen 2: dark green #154c2a)`. The `(MSG, ...)` text on the pause line is printed in UGS's console by GRBL when the machine stops, so the person at the machine sees which pen to load. Resume in UGS after swapping. |
| Tool change | Lift to Safe Z, the same comment line, then `T<n> M6 (MSG, Load pen <n>: ...)`, using the pen number. Check that your controller accepts `M6`. |
| Separate file per pen | One complete program per pen. After Generate, choose the pen under **Pen file**; Save As and Copy use the file shown. Repeat for each pen. |
| No pause | A single program sorted by pen, with comments but no stop. |

The message gives the pen number, a plain color name (black, dark green, light blue, orange, brown...) and the hex code, using the pen's display color if you changed its swatch. A pen that holds several colors lists the first three and then `+N more`. The comments never nest parentheses, which some controllers reject, and the per-pen files start with the same comment (`(Pen 2: dark green #154c2a only)`). Pen changes only add commands when there is more than one pen. After a manual swap, re-establish the same Z reference for every pen; the plugin cannot know pen lengths.

## Fills (0.2.0; wavy and zigzag 0.3.0; wavy cross-hatch and hidden-line removal 0.4.0)

Closed shapes can be filled with parallel pen lines. Open the **Pens** tab, **Fills** table (plotter mode only).

- **Which shapes:** set **Fill source** (top of the Fills section): **No fill** (no fills at all), **Fill as in the original SVG** (the default: only shapes that have a fill; an unspecified fill counts as none, since SVG would paint it black but that is almost never wanted for plotting) or **Fill all closed paths** (every closed shape; those without a fill are hatched in their outline color; presets saved with the former "hatch every closed shape" checkbox load as this). Open paths, such as a plain line, have no inside and are never filled, and a pen that holds only open paths is not listed in the Fills table. DXF has no fills, so DXF needs the override.
- **Which pen:** the pen assigned to the shape's *fill* color. A shape with a blue stroke and a red fill is outlined by the blue pen and hatched by the red pen. Fill colors appear in the color table (shown as "N fills").
- **Per-pen settings:** each pen in the **Fills** table has a one-line summary, an **Edit** button and a **Random** button. Edit opens a floating popup (no backdrop: drag its title bar to move it, and the preview behind it stays live and updates as you change a value; close it with Done, the × or Escape) with:
  - **Pattern:** None, **Parallel lines**, **Cross-hatch** (a second set at +90 degrees), **Wavy lines** or **Wavy cross-hatch** (two wavy sets, 90 degrees apart).
  - **Angle** (degrees, measured in output coordinates after the rotation setting), **Line spacing** (mm) and **Gap from outline** (mm).
  - **Wavy patterns only:** **Wave height** (how far a line swings to each side), **Wavelength**, and **Wave shift between lines** (0 keeps neighboring waves parallel, 180 swings them in opposite directions). A wavy line is drawn across the whole shape and then trimmed to the part inside it that is at least Gap from the outline, so the waves run right up to the gap on every side (their height does not push them further in). Lines whose baseline lies just outside the shape can still contribute where a wave swings in.
  - **Zigzag:** join the ends of neighboring lines so the pen stays down. Every line piece is collected first (a line is split into several pieces by holes, notches and separate lobes), then ends on neighboring lines are joined with a short straight connector wherever one is clearly acceptable. Like ends are joined (both left or both right) to make the U-turn, the shortest connectors are chosen first, each end takes at most one connector, and a connector never closes a loop, so the result is a set of continuous paths. A connector is only made if all of these hold: (1) it is short, up to three line spacings but no more than about 3 mm, and never less than 1.5 line spacings (so on coarse hatch it is at most 1.5 spacings); (2) it stays inside the shape and at least 0.85 x the gap away from the outline at every point, so it never cuts across a hole, a notch or the border margin; (3) it looks deliberate, either square-on to the lines (within about 3 degrees of perpendicular, which in a cross-hatch is the other grid direction) or running along the border (within about 3 degrees of the nearest outline's direction and close to it). The 3-degree tolerance matters: measured on the patch test file, nearly all border-parallel connectors are within 1 degree, and the few that leaned 4 to 15 degrees were the visibly off-axis lines, so a looser rule only added crooked connectors. Anything else is not made and those two ends simply stay separate lines; the plugin does not try curved or detouring connectors, which looked like noise around star tips and inside narrow letter strokes. The ends that stay unjoined are mostly real dead ends (the tips and branch ends of a shape where no neighboring line ends nearby), ends whose neighbor already has its one connector, and ends whose only possible connector would be long, diagonal or too near the border. The border gap itself does not limit how many ends join (a gap of 0.3 and 0.9 give about the same count). On the patch test file the 609 line pieces of the green region draw as about 100 paths, and a coarse 6.65 mm cross-hatch of the black region halves its separate lines.
  - **Random:** picks a pattern, angle, spacing, gap and wave settings at random for that pen. **Random fills** (above the table) does it for every pen. Click again for a new roll; Edit afterward to fine-tune.
- **Gap:** every line stops at least this far from every outline, including holes, so hatching never touches the stroke. Set 0 to run lines right up to the outline. Pieces shorter than 0.1 mm are dropped.
- **Grid and direction:** lines sit on a fixed grid so touching shapes line up, and alternate direction line to line to shorten pen travel (zigzag removes the lifts altogether).
- **Holes:** all subpaths of one SVG element are filled together with the even-odd rule, so a compound path such as a ring or a letter "O" keeps its hole. Separate elements are filled independently, with no hole logic between them.
- **Order:** within a pen, hatch is plotted after the outlines; **Hatch before outlines** flips that. **Don't outline shapes that have a fill but no stroke** drops the outline of such shapes and keeps the hatch.
- **Background:** the color picker above the preview (with an **Auto** reset) changes only the preview background, so black pens stay visible; it is remembered between sessions and never affects the G-code.
- **Preview:** hatch lines are drawn thin and without start/end markers, and are not listed under Selected path. Path numbers and the G-code include them.
- **Limits:** 20,000 lines per angle per shape and 100,000 in total; the plugin asks you to increase the spacing beyond that.

**Automatic SVG quality (0.5.40):** **Auto fit quality** on the Quality tab tries progressively coarser spacing, curve sampling and tolerance until the SVG is below about 90,000 sampled points. That leaves headroom under the 100,000-point importer guard for planning, hatch lines and output. It changes only those three SVG quality controls; the other import settings remain as configured. Auto runs only when clicked; it writes its result into the controls, and **Reimport with these settings** always uses the values currently shown. The SVG/DXF path guard is 1,000 paths/contours, but path count is separate from sampled-point count and AUTO cannot reduce it.

**Hidden-line removal** (checkbox **Hide lines covered by shapes above**, off by default, plotter mode only): SVG paints later elements over earlier ones, and a plotter cannot cover a line, so this option removes what a shape below would have drawn where a shape above hides it.
- **Which shapes hide things:** closed shapes that have a fill (explicitly, not through the "Fill all closed paths" setting). A shape with no fill hides nothing, as in the SVG itself. Fill opacity is ignored: any fill hides completely.
- **What is hidden:** the outlines and the hatch of every element *earlier* in the file, inside the covering shape's area (even-odd, so a ring's hole stays visible). It applies whatever pen is assigned; a shape set to Skip still covers what is below it.
- **Edge gap:** hatch of a covered shape stops at least its pen's **Gap** distance from the covering shape's outline, the same clearance hatch keeps from its own outline (including at wave peaks and zigzag connectors). Gap 0 runs the hatch right up to the edge.
- **Result:** a partly covered outline becomes open pieces (a closed outline whose seam is visible stays one piece); a fully covered path disappears. Pieces shorter than 0.05 mm are dropped. The message area reports how many paths were trimmed and removed. Manual start or direction picks on a trimmed outline are lost, because it becomes new paths.
- **Limits:** SVG only (a DXF has no stacking order or fills); the covering is computed on the sampled outline, so curves are approximated at the sampling tolerance; outlines of a covered shape run right up to the covering shape's edge (there is no outline margin). A very large drawing stops with a "too large" message rather than hanging.
With it off, overlapping filled shapes are each drawn in full and the plugin reports how many pairs overlap.

**Color consolidation (0.5.46):** **Group colors onto this many pens** measures each imported fill by its sampled region area instead of counting every shade/path equally. Explicit strokes receive an approximate visual-area weight. The deterministic grouping keeps neutral and chromatic colors separate, treats very dark tinted tracing artifacts as part of the black family, tries every feasible neutral/chromatic pen split and chooses the split with the lowest area-weighted Lab color error. Tiny outlier shades therefore cannot consume pens needed by major yellow, red, orange or peach regions. Pens are still numbered by first appearance, and the resulting swatches and pen assignments remain manually editable. The SVG itself and all geometry are unchanged.

**Consolidated pen view (0.5.47):** after grouping, the color table switches to **Consolidated pens**, one row per resulting pen. Its single swatch changes the preview and G-code label color for every original shade assigned to that pen; the row also reports the number of source colors, paths and approximate artwork coverage. A pen number edit moves the whole consolidated group. Switch to **Original colors** to inspect, skip or reassign individual source shades. Pen numbers no longer have an artificial 99 ceiling; they only need to be nonnegative whole numbers, with 0 meaning skip. The visible header now follows the plugin version.

**Whole-group selection (0.5.48):** every consolidated row has a Plot checkbox. Unticking it skips all original colors assigned to that pen at once. The disabled row remains in the consolidated list under its remembered pen number, so ticking it restores the complete group. A partly selected group shows an indeterminate checkbox until it is enabled or disabled as a whole.

**Per-group automatic color restore (0.5.49):** every consolidated row has an **Auto** button beside its swatch. After manually changing that group's display/label color, Auto recalculates and restores the same area-weighted representative artwork color used by automatic grouping. It changes only that group's displayed color; group membership, pen numbers, skipped colors and every other group remain untouched.

**Black and white endpoint priority (0.5.50):** when pen reduction puts a meaningful near-white region in the same neutral group as light gray, white is selected as that group's physical representative color; near-black receives the matching protection against dark gray. This preserves paper-white highlights and black outlines at lower pen counts. The endpoint must account for at least 0.5% of the artwork's measured color weight, so isolated tracing noise does not steal a pen color. When black and white must share the sole neutral pen, the normal area-weighted representative is still used because one pen cannot represent both endpoints.

**Resizable settings column (0.5.51):** drag the narrow vertical divider between the settings and preview to make the left column wider for color tables or narrower for preview and G-code work. The divider keeps enough room for both sides, supports Left/Right, Home and End from the keyboard, and resets to 330 px on a double-click. On narrow phone layouts the columns still stack and the divider is hidden.

**Parked skipped pens (0.5.52):** regrouping still uses only enabled source colors, but skipped consolidated groups no longer collide with or disappear into the newly numbered active groups. Each skipped group is assigned the next unused number after the requested active range and remains visible as an unchecked **Parked** row. For example, group to eight, skip white, then group the remaining colors to six: pens 1–6 are the active result and white remains parked as pen 7. Restoring it makes it an active seventh pen; disable or merge another pen first if only six physical pens are available.

Other limits: no nonzero fill rule, no fills in knife or laser mode, and fill settings are not saved in presets (the global checkboxes are).

## Preview arrows, fill styles, pen width, thick lines and pen order (0.5.6 to 0.5.12)

- **0.5.6, direction arrows:** each path's direction arrow now has a fixed short length (4% of the drawing size) at the path's start, so a long straight line no longer gets an arrow running along its whole length.
- **0.5.7, saved fill styles:** in the fill popup, open **Fill styles: save and reuse**. **Save style** stores the pattern, angle, spacing, gap, wave settings and zigzag under a name (saving an existing name replaces it); pick a style and **Apply to this pen** to reuse it on any pen, and **Delete style** removes it. Styles are kept in the plugin's Dashboard settings, so they survive restarts, and are shared by all artwork.
- **0.5.8, the popup remembers itself:** its position and width are saved (drag the title bar to move it, drag its right edge to resize) and restored the next time it opens.
- **0.5.9, pen width:** **Pen width (mm)** on the Pens tab (default 0.5; saved in presets).
  - **Warnings:** the popup and the message area warn when a fill's line spacing is narrower than the pen (neighboring lines overlap) or its gap is under half the pen width (the hatch touches the outline).
  - **Defaults:** new fills start at spacing 2 x pen width and gap = pen width; **Random** picks spacing, gap and wave height in ranges based on the pen width, so it never chooses lines closer than the pen can draw.
  - **To scale:** **Draw preview lines at the pen width** draws plotter lines at the real width in millimeters, semi-transparent so overlaps look darker.
- **Preview halo:** shape outlines in the preview are drawn with a thin under-stroke (a halo) so they stand out. It is the background color, so it is invisible on most colors, but a pen color that would be hard to see against the background (a dark blue on the dark theme, a pale yellow on a white background, or anything close to the background you pick) gets a lighter or darker halo instead. Hatch and wavy fill lines never get a halo, to keep dense fills readable, and the halo is not drawn in the to-scale pen-width view. It is only a preview aid and is never plotted.
- **0.5.10, a width for each pen:** the Pens tab lists every pen in use with its own **Width mm** (blank uses the default pen width). Pen widths are saved with the plugin's Dashboard settings, so they stay with pen *numbers* between jobs (pen 3 is always your 0.3 mm pen). Fill warnings, fill defaults, Random and the to-scale preview all use each pen's own width.
- **0.5.11, thick lines:** the **Thick mm** column draws every outline on that pen as a solid band of that width (0 keeps a single line). A band is made of parallel strokes one pen width apart: a thickness of 2.5 mm with a 0.4 mm pen is 7 strokes. A plain line becomes a thick bar, an open path a ribbon, a closed shape a thick border (the strokes straddle the original outline, half inside and half outside). Corners are mitered, and very sharp turns are beveled so a band never spikes outward. A closed shape's inward strokes are limited when the band would be wider than the shape can hold, and the message area says so. It applies to outlines only (hatch fills are unaffected), runs after hidden-line removal, and works in plotter mode.
- **0.5.12, pen order:** **Pen order** sets which pen plots first: **By pen number** (default), **Light to dark** or **Dark to light** (by each pen's display color; a pen with several colors uses their average), or **Nearest pen next** (starts with the pen nearest the origin, then each time picks the pen that starts closest to where the last one finished). Every pen is still plotted once, so the number of pen changes is the same either way; the order carries into the pause and tool-change commands and into the per-pen files. With `T<n> M6` the tool numbers stay the pen numbers.
- **Which paths get an outline:** every imported shape is plotted along its own outline, in its stroke color (or its fill color when it has no stroke), on the pen for that color. Hatch is added inside; it does not replace or add an outline. **Don't outline shapes that have a fill but no stroke** removes the outline of such shapes.

## Large drawings (0.5.13 to 0.5.15)

Drawings with hundreds of detailed shapes (a patch or logo with 200 subpaths and tens of thousands of curve points, such as a squadron patch) used to stop with "Containment calculation is too large" and show no preview. They now load in under a second, and fills work on them.

- **Inner contours first** finds shapes inside other shapes. Bounding boxes are computed once and only edges that can reach the inner shape are compared, so it no longer runs out of budget (the hard limit is still there, now 50 million edge comparisons, for pathological files).
- **Fills on detailed shapes:** wavy trimming, the inside-the-shape test and hidden-line removal now look only at the edges near each line, using edges filed by height, instead of every edge of every shape. On that patch: hatch 0.5 s, cross-hatch 0.7 s, wavy cross-hatch about 2 s, with hidden-line removal about 4 s.
- **Ordering:** with **Reduce travel**, outlines are ordered by distance, while hatch keeps its line-by-line sweep, which is already short and avoids a very slow nearest-line search across thousands of hatch lines. Planning no longer rescans every path at each step.
- **Preview:** each pen's hatch is drawn as one SVG path instead of one element per line, and hatch is drawn under the outlines.
- **While you type:** when a re-plan takes more than a quarter of a second, changes to fill settings, pen widths and thickness wait for a short pause in typing and the summary shows "Recalculating…".
- **Hidden-line removal and shared edges:** a line that lies on (within 0.03 mm of) a covering shape's own edge stays visible. Artwork whose shapes share boundaries, each stroked in its own color, would otherwise have its outlines chopped into many tiny pieces by rounding noise along the shared edge. With **Both pens**, outlines are inset before hidden-line clipping, so a visible neighboring outline remains eligible for the second pen even when the source regions overlap slightly.

## Duplicate lines and color pickers (0.5.16, 0.5.17)

- **0.5.16, merge duplicate lines:** artwork made of neighboring color regions (a traced logo or patch) usually stores each shared border twice, once per shape, so two pens plot exactly the same line, and a pen can even plot over a line it already drew. **Merge duplicate lines within (mm)** on the Pens tab (default 0.05, 0 = off, plotter mode) walks the outlines in plotting order and removes from each path the parts that lie within that distance of a line already going to be drawn. **A shared line is kept by** decides which pen keeps a border that two pens would both draw: **the darkest pen** (the default, so black outlines stay black), **the lightest pen**, **the pen plotted first** or **the pen plotted last** (Pen order decides those two). Darkness uses each pen's display color, so a swatch you change counts. A pen set to Skip claims nothing. If every line a pen would draw is a copy of another pen's line, that pen is left with nothing to plot (for example, a traced drawing whose black pen already outlines every region leaves the colored pens empty when black owns the lines), and the message area names it; the pen sequence and pen-change commands then skip it. The path that loses a shared edge becomes one or more open pieces; fully duplicated paths disappear; hatch fills are not merged. The message area reports how much was removed. On a traced squadron patch (205 outlines, 6 pens) it dropped 95 fully duplicated paths and cut the plotted outline from 18,013 mm to 9,571 mm, with no segment left lying on another pen's line. Because the merge also takes up to one tolerance off each end of a shared edge, lines meeting at a corner stop that much short of each other; raise the value only if neighboring lines are separated by more than 0.05 mm yet still overlap in ink (about half a pen width).
- **0.5.17, color pickers:** changing a pen's color swatch or the preview background no longer re-draws the whole drawing on every drag step of the picker. The picker applies its color when you close it (the background shows live while dragging, since that is cheap). A swatch change re-plans only when Pen order is light or dark first, which depends on the colors; otherwise it just redraws the preview.

### Traced and cut-out artwork (a patch or logo made of abutting colored regions)

Such art has no overlap: every region is cut to exactly its visible area, and the thin black "lines" between colors are really narrow black regions. Every border is therefore stored twice, once for each neighbor, and only the choice of pen is open. A good setup: **A shared line is kept by the darkest pen**, so black draws every outline (the lettering, the ring edges, the slivers between colors) and the colored pens no longer retrace them, then set **Fill source** to **Fill as in the original SVG** to give each colored region its color as hatch. On the squadron-patch test file this gave black 8,289 mm of outlines with no line drawn twice and every color filled, in about 0.4 s; raise the fill spacing for a lighter plot. Choose **the pen plotted last** instead if you would rather have the colored pens draw their own borders.

## Approach height and borders inside their regions (0.5.21, 0.5.22)

- **0.5.21, rapid down to (mm above surface):** by default the pen comes down from Safe Z to the working Z in one `G1` at the lowering feed. That is the right command for the contact move (a `G0` rapid ignores the feed and runs at the machine's top speed, which slams a pen onto paper), but at 200 mm/min a 5 mm drop is about 1.6 s per pen-down, which adds up to hours over thousands of hatch lines. Set a value such as 1 on the Tool tab and each pen-down becomes `G0 Z<surface+1>` (rapid, safely above the paper) followed by `G1 Z<depth> F<lowering feed>` for the last millimeter. 0 keeps the old behavior. Lifting and travelling stay `G0`. Plotter mode only; an approach height at or above Safe Z adds nothing.
- **0.5.22, where regions meet:** for traced or cut-out art made of colored regions, **Where regions meet** can be **One pen keeps the shared line** (the merge described above) or **Both pens, each just inside its own region**. Both moves every filled region's outline inward by half its pen width (**Border inset** overrides this amount), so neighboring regions draw side by side, one pen width apart, in their own colors, instead of on the same line. A hole's edge moves away from the hole, into the filled part, so a ring or a letter "O" keeps both its edges inside its own ink. A region too thin to move in (it can only move part of its own width) keeps its outline in place and the duplicate merge then keeps one pen's line there. It applies to shapes that have a fill in the artwork and to plotter mode, and the merge still runs afterward to clean up any leftover coincident lines. On the squadron-patch test file 203 of 205 outlines moved, all six pens kept their own borders, and no line lay on another pen's line; the cost is that both neighbors draw, so the plotted outline roughly doubles (about 18 m instead of 9.6 m). Fill hatch is still measured from the original region edge, so use a hatch gap of at least a pen width.
  - **0.5.41, derived shared boundaries:** when a smaller filled path is painted over a larger filled path, the lower path may not contain a contour along their visible color interface. The planner now detects that interface and creates the missing neighboring-pen border before pen filtering. **Both pens** keeps both inset candidates; skipping one pen removes only that pen's candidate. Hatch generation follows this boundary pass and is then clipped by the same visible-shape rules.
  - **0.5.42, redraw feedback and debounce:** changing a numeric or fill setting waits one second after the last keystroke before recalculating, so a value can be edited without starting several expensive plans. A preview overlay shows while the redraw is waiting or calculating; explicit actions such as Random, presets, and color assignment still update immediately.
  - **0.5.43, continuous shared outlines and faster preview:** derived borders now join adjacent sampled edges into continuous paths before moving them into the neighboring region. This avoids repeated pen lifts and disconnected offset fragments along one color boundary. With Declutter enabled, large jobs draw nonselected outlines in grouped SVG paths to make pan and zoom lighter.
  - **0.5.44, visible zigzag and manual reimport:** zigzag fills now clip their lines to the visible area before joining them, so safe turns can follow a border exposed by an overlaid shape. Every proposed turn still has to remain visible and clear of the outline gap. Auto fit is a one-time action; Reimport uses the numbers currently shown. Preview pan and wheel events are batched to one redraw per animation frame.
  - **0.5.45, narrow filled regions:** a filled SVG subpath that returns exactly to its start is recognized as closed even without `Z`, so converted lettering receives fill occlusion and both-pen borders. If a full-width inset materially removes a thin contour, only that contour retries a smaller inset, keeping its narrow strokes; the neighboring pen's derived border moves farther into its own region so the physical pen widths remain separated. Shared-boundary side probes also shrink when a fixed probe would jump across a narrow region. A wider pen may still print beyond the original narrow colored area; the preview and paper should be checked before plotting.
  - **0.5.46, area-aware color consolidation:** grouping many traced SVG colors onto a limited pen count now weights filled-region area, prevents tiny dark outliers from claiming a pen, and automatically balances neutral pens against chromatic pens by lowest weighted color error. The original 159-color Looney Tunes test artwork consolidates to the same eight color families as its externally reduced eight-color reference.
  - **0.5.47, consolidated pen controls:** the Pens tab can switch between one row per assigned pen and the complete original-color mapping. A consolidated swatch updates the display/label tint for its whole pen, and coverage makes major versus minor groups visible. The former 99-pen validation conflict is removed and the on-page version is corrected.
  - **0.5.48, whole-group selection:** each consolidated row can skip or restore its complete source-color group with one checkbox, while preserving the row and remembered pen assignment when disabled.
  - **0.5.49, per-group automatic color restore:** an Auto button on each consolidated row restores that group's area-weighted representative artwork color after a manual swatch edit, without rerunning or reshuffling color grouping.
  - **0.5.50, black/white endpoint priority:** meaningful near-black and near-white regions remain the representative pen colors when their reduced neutral clusters also contain intermediate grays; sub-0.5% color noise does not receive that preference.
  - **0.5.51, resizable settings column:** a draggable, keyboard-accessible divider adjusts the width of the left settings pane without affecting the separate preview/G-code divider.
  - **0.5.52, parked skipped pens:** regrouping enabled colors moves skipped groups onto unused numbers after the active range, keeping them visible and restorable without consuming the requested active pen count.
  - **Sharp corners and tight curves:** at the tip of a star the two offset lines cross inside the shape, and that crossing is the corner of the inset outline, so a star stays a clean star with one point per tip (an earlier version beveled those tips and left a doubled flap at each one). On the outside of a turn a very sharp corner is beveled instead, and on the inside of an extremely sharp one (a hairpin) the tip is cut off six offsets from the corner. Where moving a line inward folds it over itself (a curve tighter than the inset, or a neck narrower than twice the inset), the self-crossings are found and the inverted or negligible loops are cut out; a narrow neck that genuinely closes splits the outline into two separate outlines. On the patch test file all 203 moved outlines came out free of self-crossings (3 became two outlines). In a few very narrow necks (about 0.1% of points) the line can still run closer to its original edge than the inset.

## Declutter (0.5.24)

The **Declutter** checkbox above the preview hides everything that is not the drawing itself: the path numbers, the start and end points, the direction arrows and the dashed rapid (pen-up) moves between paths (and the holder's travel moves in knife mode). The outlines, hatch and fills, the knife holder overlay and the red origin cross stay. The setting is remembered between sessions and only affects the preview, never the G-code.

## Pen widths for the dashboard, and its color picker (0.5.31, 0.5.32)

- **0.5.31, pen width in the G-code:** the Dashboard's plotter (paper) view reads each pen's name, color and line width from G-code comments, so each pen change now carries them in the form it understands: `(Pen 2: dark green #154c2a)` (the pen number, a color name and the hex code, hex last), then `(Pen 2 line width 0.3 mm)` as its own comment (the pen's own width from the Pens tab, else the default pen width), then `T2 M6 (MSG, Load pen 2: dark green #154c2a)` or the `M0` form. A pen that holds several colors names its main (first) color on the first line and lists the others, by name only, in a separate `(Pen 2 also draws red, blue)` comment, so they cannot be mistaken for the pen's own color. The per-pen files start with the same comments plus `(This file plots pen 2 only)`. A test (`node dashboard.test.cjs`) runs the dashboard's real `scanTools` parser on the output and checks the tool changes, colors, names and widths it reads; it is skipped if the dashboard sources are not present. Note the dashboard only sees a pen change as a tool change when the file has `T<n> M6` lines, so use the tool-change option rather than the plain pause if you want its simulation to stop at each pen.
- **0.5.32, the dashboard's color picker:** the pen color swatches and the preview background swatch open the Dashboard's own picker (`Fluid.pickColor`) when it is there: it opens beside the swatch even when the Dashboard is zoomed, reports a color each time you let go rather than for every drag step, and has a close button. On an older Dashboard, or when the page is opened on its own, the first request is refused and the swatches fall back to the browser's picker.

## Registration cross (0.5.33)

Pens never go back in a holder in exactly the same place, so colors drawn by different pens can end up a few tenths of a millimeter out of register. **Registration cross** (Pens tab) adds a small + to the job, left of and below the artwork (**Distance from the artwork**, default 8 mm; **Cross size**, default 6 mm), at known work coordinates, so every pen can be brought back to the same point:

- **One program with tool changes** (`T<n> M6`, or the pause): the first pen plots the cross. Before each later pen change the pen lifts and moves over the cross, and the message gives the exact command, for example `Register: center the tip on the cross at X-8 Y-8, then send G10 L20 P1 X-8 Y-8`. Swap the pen, jog its tip onto the center of the cross, send that command (it tells the controller the tip is at the cross, shifting the work position to match), and resume. After the change the pen draws the cross again, on top of the first one, so a pen that is still off shows as a doubled mark. Untick **Every pen draws it** if you want only the first pen to draw it.
- **Separate file per pen:** the first pen's file draws the cross and says so in its header; each other file's header says to center the pen on the cross and send the `G10 L20 P1` command before running it, and (with **Every pen draws it**) starts by plotting the cross for a visual check.
- **Notes:** keep the cross on the paper (make the distance fit your margin). The comments never contain sizes in millimeters, which the Dashboard would read as a pen width. GRBL does not accept jogging during an `M0` hold, so use a controller that handles `M6` (FluidNC does) or the separate files. The cross is shown in the preview (and kept by Declutter), and the message area gives its coordinates and the command.

## The preview keeps its view (0.5.34)

Zoom and pan now stay put when you change a setting (fills, pens, borders, pen width and so on), so you can stay zoomed in on a detail while you adjust it. The view re-fits to the drawing only when the artwork changes (a new file, the example or the calibration drawing) or when a change moves the artwork itself (scale, rotation, origin or origin bounds), because the old view would then be looking at the wrong place. Re-importing the same file (Reimport, or a preset that changes the import settings) keeps the view too. The **Fit** button always re-fits.

## Registration corner, and hatch gap with both pens (0.5.35)

- **Registration cross corner:** choose bottom or top, left or right, and set the **X** and **Y** distance outside the artwork separately (default bottom left, 8 mm each).
- **Hatch gap with "Both pens, each just inside its own region":** the hatch gap is now measured from the moved outline, not the original region edge. The hatch stops its **Gap** short of the outline's inner side (inset plus half the outline pen's width), so hatch tips no longer merge into the outline. Only applies in that mode.

## Registration cross position (0.5.36)

The cross center is the given X / Y distance from the edge of the artwork as imported (its bounding box), so "8" is exactly 8 mm. Before, it was measured from the drawn lines, which sit a little inside when borders are drawn "just inside" their regions, so the numbers came out a fraction of a millimeter off.

## Hatch gap from the outline's edge (0.5.37)

The fill **Gap from outline** is now measured from the outer edge of the drawn outline to the center of a hatch line, in both border modes (before, with "One pen keeps the shared line", it was measured from the outline's center, so the two pens overlapped by half a line). A gap of half the pen width therefore puts the hatch pen's edge just against the outline's edge, and a bigger gap leaves clear paper. Shapes whose outline is not plotted (the option to skip unstroked shapes is on, or the outline's color is set to Skip) keep the old behavior, measured from the region edge.

## Install

Copy these files into `~/.ugs/dashboard-plugins/plotter-studio/` on the computer running UGS:

`plugin.json`, `index.html`, `style.css`, `app.js`, `dropdowns.js`, `core.js`, `importer.js`, `geometry.js`, `dxf-importer.js`

Then reload Dashboard and choose **Plotter Studio** under Plugins. No Platform rebuild or UGS restart is needed. `sample.svg`, `sample-colors.svg` (five colors) and `sample-fills.svg` (a ring with a hole and a triangle, both filled) `sample-overlap.svg` (three overlapping filled shapes, for hidden-line removal) and `sample-shades.svg` (nine shades of red, blue, green and black, for color grouping) are included for testing.
